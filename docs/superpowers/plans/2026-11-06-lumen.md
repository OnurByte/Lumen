# Lumen Implementation Plan

**Goal:** Deliver the supervised, two-character Turkish debate studio specified in `LUMEN_PLAN.md`.
**Architecture:** Tokio daemon owns the journal and director. GPUI Studio and Bevy stage attach over local sockets; voice and external connectors remain replaceable.
**Spec:** `LUMEN_PLAN.md`, preserved unchanged from the attachment.

## Constraints
Rust product code; Python only for required ML runtimes. No mandatory web runtime. Audience text is untrusted. Playback acknowledgments alone establish audible dialogue. Closing Studio must not stop the daemon. No publishing or stream start without operator action.

## Implementation sequence
- [ ] Feasibility: record installed tools, dependency licenses and versions; compile independent GPUI and Bevy launch spikes; validate local IPC. Measure actual audio/capture and Turkish TTS when available. Keep missing live credentials and measurements explicit.
- [ ] Protocol and storage: typed session/turn/utterance/generation identifiers, bounded MessagePack frames, versioned commands/events, SQLite WAL journal. Test malformed frames, oversized inputs, replay order and transaction failure.
- [ ] Debate: deterministic floor/director with pause, cancel, interrupt, skip and emergency stop; reject stale generation acknowledgments. Test interrupted queued audio never enters transcript and no overlapping floor grants.
- [ ] Providers and voice: independent per-agent contexts, streaming OpenAI-compatible adapter and simulator, cancellation/timeouts, speech segment moderation, PCM sequence validation and arbiter. Test provider failure, cancellation and partial playback.
- [ ] Audience and packs: TOML personas/positions/formats, History Clash example, bounded deduplicated fair question selection, user cooldowns and expiry. Test hostile chat stays data and bursts stay bounded.
- [ ] Runtime: daemon socket server, durable event publication, scenario runner and simulated 30-minute replay. Test reconnect, restart recovery, pending-model emergency stop and deterministic replay.
- [ ] Broadcast: independent Bevy 1080x1920 stage with captions and audio-driven avatars; GPUI operator pages and immediate controls; CPAL/PipeWire routing; OBS websocket adapter; isolated TikTok connector with simulator fallback.
- [ ] Delivery: setup and license documentation, failure/reconnect scenarios, resource/latency reporting, actual hardware capture and supervised two-hour broadcast acceptance. Record unmet gates rather than substitute simulated evidence.

## Review focus
Cancellation racing playback must not commit unplayed text. Daemon restart must not replay old audio. Unavailable providers must lead to bounded recovery or pause. Malformed audience/IPC input must not allocate unlimited memory or grant controls. Studio disconnect must leave operator reconnection available.

## Verification
Use focused Cargo tests per component, then workspace format/check/test/clippy. Replay fixtures must exercise real director and storage paths. Run GUI/capture/audio checks separately from simulation. Record commands and results in `docs/feasibility.md`; advance gates only with matching evidence.
